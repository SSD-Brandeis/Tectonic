# YCSB-IVS in X-Bench

A spec that reproduces the workload of [YCSB-IVS](https://github.com/dliyanage/YCSB-IVS)
(TPCTC 2025, "increasing value sizes") exactly as the repository ships it: its only extend workload,
`workloads/workloada-extend` (unmodified), driven the way the shipped
`experiment_scripts/experiment_mongodb.sh` drives it on the primary database:

1. a **load phase**: 101,000 records of 10 fields × 100 bytes;
2. then iterations of
   - an **extend phase**: 10,000 operations, `extendproportion=1`, uniform; every operation reads one
     field of a record and writes it back with `extendfieldlength` (100) random bytes appended, so
     values grow over time;
   - a **run phase**: 10,000 operations, 50/50 reads and updates, uniform; updates write one field
     whose length is drawn from a histogram of the record sizes after the extend phase
     (`fieldlengthdistribution=histogram`).

The script exits in iteration 5 right after its extend phase (`if [ $iteration -eq 5 ]; then exit`),
so the workload is load + 5 extend phases + 4 run phases.

| File | Request distribution | Records | Ops per extend / run phase | Extend / run phases |
| --- | --- | --- | --- | --- |
| `uniform.spec.json` | uniform | 101,000 | 10,000 / 10,000 | 5 / 4 |

How the YCSB-IVS operations map to X-Bench (one section, so all phases share the valid keys):

- load → `inserts` with values of FileClient's 10-field rendering (1,090 bytes);
- extend → `merges` whose operand is the one-field rendering of the increment (109 bytes). Execute
  with `tectonic-cli execute --merge-mode append`, which reads the value and writes it back with
  the operand appended, exactly what YCSB-IVS's `DB.extend` does;
- run → `point_queries` + `updates`. The update field lengths per run phase are the output
  distribution of YCSB's `HistogramGenerator` for the histogram YCSB-IVS builds from the database;
  since that depends on runtime state, they are taken from an independent YCSB-IVS run.

Generated by `run_scripts/run_ycsb_derivatives_fidelity.py`, which also runs the comparison.
